مستندات فنی اعتبارسنجی

پروکسی‌های تلگرام چگونه اعتبارسنجی می‌شوند؟

باز بودن یک پورت، دلیل سالم‌بودن پروکسی تلگرام نیست. این پروژه بررسی می‌کند که درخواست از پروکسی عبور کند و پاسخ موردانتظار از دیتاسنتر واقعی تلگرام برگردد.

صحت‌سنجی مستقل: آمار و وضعیت به‌روز را از index.json بخوانید؛ این مقاله عمداً آمار زنده ثابت ندارد.

دقیقاً چه چیزی تأیید می‌شود؟

سه دور آزمایش سرتاسری

برای قرارگرفتن در فهرست تأییدشده، پروکسی باید در هر سه دور تست موفق شود. درخواست req_pq_multi ارسال و پاسخ دیتاسنتر همراه با nonce تصادفی تولیدشده کنترل می‌شود.

بررسی DNS و هویت سرور

نام دامنه قبل از تست به آدرس IP تبدیل می‌شود. اگر دامنه چند آدرس IPv4 داشته باشد، همه آدرس‌ها باید در آزمایش موفق شوند.

انواع FakeTLS و Secure و Classic

برای نوع FakeTLS با پیشوند ee، بررسی اضافی HMAC مربوط به ServerHello انجام می‌شود؛ نوع dd و نوع کلاسیک با بررسی‌های متناسب با پروتکل آزموده می‌شوند.

تست فراتر از TCP

باز بودن TCP یا موفقیت یک handshake ساده، اثبات دریافت پاسخ از دیتاسنتر تلگرام نیست.

زنجیره مراحل اعتبارسنجی

ترتیب مراحل

جمع‌آوری منابع عمومی ← پردازش secret مطابق قواعد TDLib ← بررسی DNS ← حذف تکراری‌ها ← بررسی TCP و handshake ← دریافت پاسخ MTProto ← تکرار سه دور ← بررسی تاریخچه ← انتشار.

این تست چه چیزی را تضمین نمی‌کند؟

موقعیت جغرافیایی تست

نتایج سرعت و اتصال فقط مربوط به موقعیت سرور اجراکننده است. موفقیت تست از آن موقعیت به معنای دسترسی از تمام کشورها یا اپراتورها نیست.

حریم خصوصی اپراتور

اپراتور پروکسی IP و برخی اطلاعات اتصال را می‌بیند. این آزمایش هویت اپراتور یا کانال‌های تبلیغاتی احتمالی را بررسی نمی‌کند.

پایداری در آینده

تأییدشدن در یک اجرای قبلی، تضمین اتصال در آینده نیست؛ داده‌ها به شکل دوره‌ای بازسازی می‌شوند.

راستی‌آزمایی مستقل

مشاهده سورس و آزمون‌ها

سورس Python و تست‌ها و معیارهای فنی در ریپوزیتوری GitHub منتشر شده‌اند و می‌توان آن‌ها را جداگانه بررسی کرد.

داده‌های قابل‌خواندن ماشین

فایل index.json آمار و محل اجرای تست را ارائه می‌کند؛ فایل health.json سلامت منابع و علت ردشدن داده‌ها را ثبت می‌کند.
