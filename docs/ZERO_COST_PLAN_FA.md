# برنامه ارتقای بدون هزینه Free-Telegram-Proxy

**مبنای تحلیل:** شاخه عمومی `main` ریپوی `0xRadikal/Free-Telegram-Proxy` در ۲۶ اکتبر ۲۰۲۶؛ برای اجرا روی هر commit جدید، CI باید دوباره بررسی شود.

## محدودیت‌ها

- هیچ سرور جدیدی لازم نیست.
- هیچ دامنه، سرویس API پولی، یا Runner پولی لازم نیست.
- GitHub Actions روی Standard Runner ریپوی عمومی رایگان است؛ GitHub زمان دقیق cron را تضمین نمی‌کند.
- GitHub-hosted Runner معیار اتصال واقعی از ایران یا روسیه نیست. از آمار `runner.loc` در `index.json` تنها برای توضیح محل همان آزمایش استفاده شود.
- سرور آلمان اختیاری است؛ **نباید** برای ریپوی عمومی Self-hosted Runner شود.
- صرفاً تست کردن port / ping / DNS از شبکه ایران، تأیید کامل MTProto نیست. دسترسی ایرانی فقط در صورت اجرای تست End-to-End از آن شبکه قابل ادعاست.

## تغییر آماده‌شده در این بسته (بدون تغییر در سیستم انتشار)

1. `tools/check_freshness.py`: بررسی آفلاین فایل‌های `index.json` و `health.json` و کشف داده کهنه، Timestamp ناهمخوان، خطا در funnel، شمارش‌های ناسازگار و سقوط شدید تعداد لینک‌ها. این اسکریپت فقط داده را می‌خواند و در صورت اجرا روی Actions نتیجه را در Job Summary می‌نویسد.
2. `.github/workflows/publication-health.yml`: اجرای جداگانه با `contents: read` روی GitHub-hosted Standard Runner؛ هر نیم ساعت و دستی. نه توکن اضافی نیاز دارد، نه انتشار را انجام می‌دهد، نه تغییری در داده می‌دهد.
3. `tests/test_check_freshness.py`: کنترل‌های مثبت و منفی آفلاین.
4. `tools/optional_germany_spotcheck.py`: ابزار **اختیاری** روی سرور موجود آلمان، به‌طور پیش‌فرض Dry-run و بدون شبکه. اگر صریحاً `--live` داده شود، حداکثر ۲۵ پروکسی، ۴ اتصال هم‌زمان، و ۳ دور تست می‌کند؛ پیش‌فرض ۲۰ / ۳ / ۲ است. فقط summary چاپ می‌کند؛ **secret، آدرس و IP پروکسی‌ها را در گزارش چاپ نمی‌کند**. هیچ GitHub token یا نوشتن در repo نیاز ندارد.
5. `tests/test_optional_germany_spotcheck.py`: کنترل‌های آفلاین و پروبر ساختگی؛ **جایگزین تست زنده MTProto نیستند**.

## راه‌اندازی مرحله اول: فقط GitHub

**این بسته را روی یک branch جدید مرور و تست کنید.** پس از تأیید و merge:

```bash
python -m pytest -q tests/test_check_freshness.py tests/test_optional_germany_spotcheck.py
python3 tools/check_freshness.py --max-age-minutes 65 --min-verified 20
```

برای اجرای دستی Watchdog در GitHub: Actions → Publication health (read-only) → Run workflow.

**نکته مهم:** `.github/workflows/ci.yml` فعلی برای تغییرات `tools/**` یا `tests/**` علاوه بر unit test یک E2E دو دوری واقعی انجام می‌دهد. بنابراین ساخت PR خودکار می‌تواند پروکسی‌های عمومی را واقعاً تست کند. قبل از باز کردن PR به این رفتار توجه شود.

هشدار Watchdog از نوع failed workflow است؛ ارسال خودکار پیام تلگرام یا ایمیل تضمین نشده. در صورت نیاز، از اعلان‌های خود GitHub یا سامانه هشدار موجود و رایگان استفاده شود. زمانی که کل GitHub در دسترس نیست، این workflow نیز ممکن است اجرا نشود؛ بنابراین مانیتور مستقل خارج از GitHub محسوب نمی‌شود.

## سرور آلمان — فقط در صورت انتخاب مالک

روی ماشین مورد اعتماد که سورس ریپو و وابستگی‌های پروژه در آن نصب شده‌اند، از **ریشه ریپو** اجرا شود:

```bash
python -m tools.optional_germany_spotcheck --source resilient/proxies.json
# یا: python tools/optional_germany_spotcheck.py --source resilient/proxies.json
```

خروجی پیش‌فرض `mode: dry-run` است و هیچ ارتباط شبکه‌ای با پروکسی برقرار نمی‌کند.

فقط بعد از مرور و پذیرش بار شبکه:

```bash
python -m tools.optional_germany_spotcheck --source resilient/proxies.json --max-proxies 10 --concurrency 2 --rounds 2 --live
```

این فرمان حداکثر ۲۰ تلاش تست MTProto روی ۱۰ پروکسی مستقل انجام می‌دهد (کمتر در صورت شکست در دور اول). نه `sudo` نیاز دارد و نه تنظیم SSH یا systemd را دست می‌زند. هیچ وظیفه زمان‌بندی‌شده‌ای روی سرور نصب نمی‌کند. خروجی فقط به ترمینال می‌رود.

**هیچ‌وقت** نتایج این ابزار را خودکار جایگزین `verified/` نکنید: نمونه کوچک است، آزمون از دو نقطه در یک لحظه هماهنگ نیست، و موقعیت جغرافیایی اجرای ابزار از بیرون اعتبارسنجی نشده است.

## Safety / Rollback

- **با ثبت PR فایل‌ها فقط در شاخه پیشنهادی اضافه می‌شوند؛ `main` و سرور آلمان تغییر نمی‌کنند.** تا قبل از merge، این تغییرات فعال نیستند.
- بخش GitHub در صورت merge نیز فقط یک workflow خواندنی اضافه می‌کند؛ خروجی و فرآیند انتشار موجود را تغییر نمی‌دهد.
- برای برگشت: workflow جدید `publication-health.yml` را از branch بعدی حذف کنید؛ `tools/check_freshness.py` خود تغییری در وضعیت اجرا ایجاد نمی‌کند.
- استقرار روی سرور آلمان لازم نیست. اگر اجرا شود، تنها یک برنامه دستی و موقت است.
- تست‌های این بسته آفلاین‌اند و اجرای واقعی روی GitHub/آلمان/شبکه ایران را **اثبات نمی‌کنند**. مسیر اعتبارسنجی بیشتر، ابتدا PR و سپس بررسی دستی logs است.
